From a 99+ Trip Backlog to an Inbox You Can Clear

A Driversnote inbox of ninety-nine trips offered two ways through: approve them all on faith, or review them one at a time until the driver gave up.

Active users log fourteen to sixteen trips a week, so the pile refilled faster than anyone could keep up. Each trip faded from memory between sessions, and approvals turned careless or stalled. Neither option left a driver sure the logbook was right.

I reframed the inbox around the trips that needed attention, and built Smart Inbox.

Ready and Needs Review, Assigned by Criteria the User Sets

The inbox treated every trip the same, so the user did all the sorting.

I split it in two. Trips that meet every rule they set, a high-confidence category, named start and end, a filled note, land in Ready and approve in one action. The rest land in Needs Review.

The user stopped sorting the inbox; it arrived sorted.

Each Review Makes the Next One Lighter

A split inbox only pays off if the user comes back to it.

Ready clears the trusted trips in one confident batch. The one-by-one work in Needs Review teaches the system, so next time more trips arrive already in Ready. The reward used to be an empty screen and an upsell; now it is the sum the logbook just earned them.

Each pass leaves less to review and more to claim.

96 Testers, From a Card They Read as Old News to a Feature They Set Up

The first testers read the card for Smart Inbox as the app telling them what it already did.

A new feature that needed switching on looked like nothing new, and testers scrolled past it without setting it up. Across two rounds and ninety-six people, I rebuilt the card to announce a new feature, with a thirty-second setup and a button of its own. By the second round, testers read it as something new and set it up on purpose.

The ninety-nine-trip pile that used to sit untouched now arrives as two buckets, one a driver clears in a tap.
